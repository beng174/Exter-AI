## Surprises and discoveries
The web service owns the persistent media disk; workers cannot read it. The existing artifact content store is reused as a pure file library. Its kernel routes/flags are not activated; media uses a separate narrowly authenticated step endpoint. Public actor Store metadata/documentation is available without running a paid actor. The better established actor candidate is curious_coder/facebook-ads-library-scraper: public metadata checked 5 Nov 2026 reports a 23 Oct modification, about 50,000 users, $0.00075 per returned ad and an additional $0.00005 start event at its default 512 MiB. Current billing is PAY_PER_EVENT, so the media guard must include both known event types rather than assume a purely per-result charge. Its public contract does not promise direct missing-ID retrieval. Selected automation_craft/facebook-ads-library-scraper instead: build 1.3.12, last modified 3 Nov, 12,926 successful runs in the last month, $0.0005 per ad-result plus $0.00005 start at 256 MiB. Verified the public default build definition: pageIds, adArchiveIds, countries, deliveredAfter/Before, hard maxAds, and explicit false optional enrichments. No provider run was started.
